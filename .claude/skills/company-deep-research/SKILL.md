# 公司六问深度研究

## 目标与边界

生成一份有证据、有反向声音、有定价推演的公司研究，而非公司介绍或交易指令。沿用用户提供的 SDGR 六问报告的结构和浅底深蓝研报视觉；不照搬其数字、判断或平台代码。

- 研究业务及证券定价：使用本技能。默认研究未来一至三年的业务，未来六至十八个月的状态切换。
- 明确要求横纵方法或历史生命历程：保留百科研究的独立报告。
- 明确要求买卖点、仓位、下单、止损或是否现在投入资金：转交交易研究；没有该技能时说明另需交易分析，不能在本稿偷加仓位。
- 不把上述其他技能当依赖。单独复制本目录即可运行；读取所有引用均相对于本 `SKILL.md`，脚本从自身位置寻找资源。

## 先读取的最小充分集合

1. 读取 [research-method.md](references/research-method.md)，执行六问及反思闭环。
2. 读取 [data-and-markets.md](references/data-and-markets.md)，确认身份、时点、跨市场与数据能力。
3. 读取 [valuation-and-financials.md](references/valuation-and-financials.md)，用可复算的财务和定价框架。
4. 写稿时读取 [report-template.md](references/report-template.md)、[report-schema.md](references/report-schema.md) 和 [html-design.md](references/html-design.md)。
5. 迁移、安装或检查依赖时读取 [portability.md](references/portability.md)；方法论来源与改写边界见 [provenance.md](references/provenance.md)。

## 执行闭环

### 0．锚定任务与能力

确认公司、上市市场、标准代码、报告日、用户关注点和输出目录。同名或多上市主体影响结论时追问；其他信息充分就直接开做。日期取执行器实际日期，不从示例日期推断当前。港股代码保留五位，美股确认 ADR 与普通股换算。

检查当前执行器是否具备联网搜索、公开网页读取、文件写入和 Python 3.9 以上运行能力。按能力而非专有工具名调用：已授权的金融数据工具可选增强；无此能力直接走公司 IR、交易所／监管公告及公开网页。不要要求安装某 IDE 的金融入口，不要凭名称猜插件 API。无联网时，只能基于用户提供资料生成明确时点的历史研究；无资料则交付资料缺口与研究骨架，不能假装完成实时公司研究。

### 1．建立证据底稿

先拿最近已披露年报／季报、近期业绩材料、业务分部、行情快照、股份和现金负债，再扩展行业及同业。财务尽量取五至十年与最近八至十二季；上市时间短按实际可用期。未提供足够历史时显示窗口缺口，不伪造趋势或估值分位。

记录每个事实的来源 URL、机构、发布日期、统计期、访问日及会计口径，给来源编号 `S1`、`S2`。区分一手事实、管理层指引、卖方预测、研究者测算和未知。以研究日可获得信息为限；历史研究禁止引用其后披露信息。保存证据底稿在对象目录，不把搜索摘要直接冒充读过的公告。

可并行检索行业、商业与竞争、财务与市场定价；没有子代理时串行执行同一流程，质量标准不变。不要硬依赖多代理或某个搜索服务。

### 2．按六问研究，不按数据工具返回顺序写作

| 问题 | 必须落下的产物 |
| --- | --- |
| 行业驱动与供需 | 可计价产品／服务的边界、驱动硬度、供需平衡表、瓶颈与反向证据 |
| 商业模式 | 分部收入、客户价值、计费单位、确认与回款、单位经济、增长与脆弱点 |
| 地位与颠覆 | 同业可比口径、真正争夺同一预算的竞争者、技术／产业代际、价值迁移与护城河证伪 |
| 股价与非共识 | 估值口径桥、价格反推假设、历史／同业对照、三情景、共识证据与非共识验证 |
| 财务与风险 | 盈利—现金桥、资产负债与稀释、压力测试、短中长期风险及领先信号 |
| 综合状态 | 四类状态逐项判断、主导与次要状态、切换条件、最可能／最危险／最乐观路径及跟踪清单 |

每轮拿到信息后检查：为什么、同业是否一致、放进历史周期、最强反证、会怎样影响下一验证点。有实质缺口就继续查；没有新增决策相关证据才收敛。优先查会改变主判断的三至五个关键变量，不为凑篇幅堆新闻。

### 3．自下而上复算，再把结论放首屏

计算关键收入驱动、利润／现金桥、股权到企业价值、反向估值及情景敏感性，保留公式和输入出处。用 [valuation-and-financials.md](references/valuation-and-financials.md) 的约束；亏损公司不要拿负 PE 证明便宜。

写成“证据 → 机制 → 定价影响 → 反例／证伪”，不能只有表格。首屏给一句话本质、四状态卡、关键指标卡、主要非共识和下一验证点。四状态不是互斥的概率桶，允许主导与次要并存；证据不足可明确无法判断，但须具体解释缺了什么。

### 4．统一数据结构与生成

按 `report-schema.md` 编写 `<公司>_公司深度研究.json`。材料不足且没有可核实一手来源时用 `mode=draft` 输出醒目标记的六问缺口骨架，允许零来源，不伪造primary；不能称已完成深研。数字图表／表格附近必须带 `sources` 和 `period`，单位写在指标或图表上。以事实为输入，以 Markdown 和 HTML 为输出；不把已有同学稿数字当本次核实数据。

从当前已加载技能目录解析 `SKILL_DIR`。下列命令中的变量是说明用的路径占位，执行前替换为实际发现的技能路径，不保留硬编码机器路径：

```bash
python3 "$SKILL_DIR/scripts/validate_report.py" "$REPORT_JSON"
python3 "$SKILL_DIR/scripts/render_report.py" "$REPORT_JSON" "$REPORT_HTML" --markdown "$REPORT_MD"
python3 "$SKILL_DIR/scripts/validate_report.py" "$REPORT_JSON" --html "$REPORT_HTML"
```

核心渲染仅依赖 Python 标准库，无需 `pip install`、Node、浏览器、PDF 引擎、CDN 或其他 skill。内联 SVG 提供趋势图，原始表始终存在；JS 只增强图表切换，无 JS 不影响阅读。不要为单篇改 CSS，也不要调用横纵研究转换器。

### 5．双重质检

自动检查结构、日期、市场代码、来源编号、数值有限性、表格对齐、图表缺值、离线资产及 JSON／HTML 一致性。脚本验证通过不等于财务事实正确。

研究者再人工检查：

- 六问是否实际回答，行业供需是否不是空泛 TAM，收入确认是否与订单／ACV 区分。
- 最新已披露期、行情真实交易时点、币种／财年／股份口径是否一致，数字是否复算。
- 非共识是否有共识证据；没有则标“待验证假设”，不声称市场普遍知道。
- 状态判定是否分清历史发生、当前状态与未来路径；回撤不自动等于估值压缩。
- 每个关键结论是否有支持、反证与验证节点；未知是否保留。
- HTML 是否有可点击 ASCII 目录、临近数据的来源、手机响应式与风险说明。

若环境有 Node，执行 `node --check "$SKILL_DIR/assets/report.js"`；没有也可运行核心链路。开发或迁移时运行 `python3 "$SKILL_DIR/scripts/test_skill.py"`。修改脚本／资源后重跑测试并重新生成示例。

### 6．交付与后续调用

输出 `<对象目录>/<公司>_公司深度研究.html`、同名 `.md` 和 `.json`，与横纵／交易报告共存。先简述核心判断、主要非共识、验证点和未解决缺口，再给阅读文件。发布、上传、发群、Git 提交遵从所在项目的独立授权和规则，不是本技能必需依赖。

推荐调用语句：“使用 company-deep-research 研究 `<市场><代码><公司>`，按六问完成证据、估值和四状态判断，生成独立 HTML；不要做仓位与买卖点。”

## 不可越过的底线

- 不编造数字、来源、检索能力、同行排名或一致预期；缺项写“暂缺／未披露／不适用”，不能填零。
- 不从同学样例直接继承当前行情、行业份额、预测或结论。演示夹具必须 `mode=demo`；正式研究用 `mode=research`，资料不足骨架用 `mode=draft` 且醒目标记尚未完成深研；research与draft均禁止演示源。
- 不把管理层目标当实现，不把合同最高金额当必然收入，不把调整后利润当法定利润。
- 不把基本面增长与估值扩张机械分摊到百分比；涉及归因使用正确公式并标清非因果解释。
- 不嵌入任何认证令牌、账户、私人机器目录、平台注入脚本或专有技能运行时。
- 始终保留完整免责声明，生成器会自动附加：

> 以上内容基于公开数据和量化分析，仅供参考，不构成投资建议。市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。
